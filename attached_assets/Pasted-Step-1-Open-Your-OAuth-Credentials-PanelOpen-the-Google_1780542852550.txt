Step 1: Open Your OAuth Credentials PanelOpen the Google Cloud Console.In the top search bar, type "APIs & Services" and select Credentials.  Look under the OAuth 2.0 Client IDs table and click on your primary web application credential name to edit it. (If you don't have one yet, click + Create Credentials -> OAuth client ID -> select Web Application).  Step 2: Configure Authorized JavaScript OriginsThis section acts as a security firewall. It tells Google exactly which web domains are allowed to execute client-side scripts to prompt the Google Sign-In pop-up window. If an unauthorized site tries to hijack your Client ID, Google blocks it instantly with an origin_mismatch error.  Scroll down to the Authorized JavaScript origins section, click + Add URI, and add these entries:  http://localhost:3000 (Or whatever local port you use to test your React frontend locally).[https://citizen-science.org](https://citizen-science.org) (Your official apex production domain).⚠️ Rules for Origins: Only include the protocol (http:// or https://) and the clean domain name. Do not add paths, trailing slashes, or routing wildcards (e.g., [https://citizen-science.org/](https://citizen-science.org/) will throw an error).  Step 3: Configure Authorized Redirect URIs (The Callback)Once a user clicks their email address and authenticates with Google, Google needs to know exactly where to securely send that user back to with their private login payload.Scroll down to Authorized redirect URIs, click + Add URI, and add your callback targets:  http://localhost:3000/api/auth/callback/google (Your local developer callback loop).[https://citizen-science.org/api/auth/callback/google](https://citizen-science.org/api/auth/callback/google) (Your official live web production callback path).💡 Note on paths: Depending on what authentication engine your Replit Agent generated (like Passport.js, NextAuth, or custom Express routing), that trailing path might vary slightly. Standard variants include /auth/google/callback or /api/auth/callback/google. Check your server’s authentication router file inside Replit to verify the exact string.  Step 4: Save and Sync Your KeysScroll to the bottom of the Cloud Console page and click Save.Copy your Client ID and Client Secret strings from the right-hand panel.Head straight back to your Replit workspace environment panel (.env), update your global variables (GOOGLE_CLIENT_ID and GOOGLE_CLIENT_SECRET), and push the commit over to GitHub so your Cloud Run container syncs the variables immediately!  Once those environment values match, testing sign-ins on your custom domain should transition smoothly. Let me know if you run into an exact routing path discrepancy when your agent wires it in!
