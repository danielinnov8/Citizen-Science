# Workspace

## Overview

pnpm workspace monorepo using TypeScript. Each package manages its own dependencies.

## Stack

- **Monorepo tool**: pnpm workspaces
- **Node.js version**: 24
- **Package manager**: pnpm
- **TypeScript version**: 5.9
- **API framework**: Express 5
- **Database**: PostgreSQL + Drizzle ORM
- **Validation**: Zod (`zod/v4`), `drizzle-zod`
- **API codegen**: Orval (from OpenAPI spec)
- **Build**: esbuild (CJS bundle)

## Required Secrets

Set these in Replit Secrets (never in source code):

| Secret | Purpose |
|--------|---------|
| `SESSION_SECRET` | Signs the `cs_session` auth cookie |
| `GEMINI_API_KEY` | Powers the AI copilot, field-notes analyzer, and avatar brain |
| `RESEND_API_KEY` | Sends outreach emails via Resend (resend.com); domain `citizen-science.org` must be verified in Resend with SPF + DKIM TXT records |
| `GOOGLE_CLIENT_ID` | Google OAuth "Continue with Google" (optional) |
| `GOOGLE_CLIENT_SECRET` | Google OAuth (optional) |
| `YOUTUBE_API_KEY` | Finds verified science video clips in chat (optional) |
| `ELEVENLABS_API_KEY` | Voices for the talking avatar feature (optional) |
| `DID_API_KEY` | Live avatar streaming via D-ID (optional) |

## Key Commands

- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- `pnpm --filter @workspace/api-server run dev` — run API server locally

See the `pnpm-workspace` skill for workspace structure, TypeScript setup, and package details.

## Artifacts

- **`artifacts/api-server`** — Express 5 API server. Auth routes under `/api/auth`: `POST /register`, `POST /login`, `POST /logout`, `GET /me`, plus Google OAuth `GET /google` (start, PKCE + state in signed cookies) and `GET /google/callback` (create-or-link user by email, set session cookie, redirect to `/login`). Sessions use a `cs_session` httpOnly signed cookie (30-day TTL); passwords are scrypt-hashed (`scrypt$salt$hash`, no external deps) in `src/lib/auth/`. `requireAuth` middleware (in `src/middlewares/`) gates the agent routes and `/me`. `app.ts` sets `trust proxy` and uses `cookie-parser` with `SESSION_SECRET`. Google OAuth uses the user's OWN `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` secrets (not a Replit connector); redirect_uri is derived from `REPLIT_DOMAINS` as `https://<domain>/api/auth/google/callback` — register both dev and prod callback URLs in Google Cloud Console. Other routes: `/api/healthz`, `POST /api/agent/chat` (SSE streaming, Gemini-backed science copilot), and `POST /api/agent/process-observation` (Gemini-backed field-notes analyzer). Both agent routes use `@workspace/integrations-gemini-ai-server`, which wraps `@google/genai` (model `gemini-2.5-flash`) using the user's own `GEMINI_API_KEY` — chosen because the Replit AI proxy (used by the OpenAI lib) is only reachable inside Replit and fails on Cloud Run. The chat route calls `streamChat(systemPrompt, messages, { signal, maxOutputTokens, useSearch })`, which maps assistant→`model`, trims leading non-user turns, and yields `StreamChatChunk` objects (`{ text?, sources? }`). When `useSearch` is true it enables the built-in Google Search tool for grounding and keeps thinking ON (with `thinkingBudget: 0` the model never decides to call Search and just answers from training data — known gotcha); when false it disables thinking for low latency. Grounding metadata (`groundingChunks[].web`) is de-duped and emitted as a single trailing `{ sources: [{ title, url }] }` chunk. The chat route runs the grounded pass first (with a larger 4096 token budget for thinking), and if it fails before any text is streamed (and the client hasn't disconnected) it gracefully falls back to an ungrounded pass via `req.log.warn`; SSE now also emits `{ sources }` events. The lib also exports `researchWithSearch(prompt, opts)` — a one-shot grounded call returning `{ text, sources }` — as the reusable web-research foundation. Note: Gemini source URLs are `vertexaisearch.cloud.google.com/grounding-api-redirect/...` redirect links and the `title` is the publisher domain. The process-observation route uses `analyzeFieldNotes` (with a `responseSchema`) using the user's own `GEMINI_API_KEY` secret (not Replit's managed Gemini integration — the user explicitly chose their own key); it validates a non-empty `rawText` body and returns `{ success, data }` structured JSON (summary, category, observations, tags, location, measurements, observedAt, species). Both agent routes are gated by the `requireAuth` middleware (valid `cs_session` cookie required). Stream cancellation on the chat route listens on `res.on("close")` (not `req`) and aborts the upstream Gemini request (via `AbortSignal`) when the client disconnects. Note: `build.mjs` externalizes `@google/*`, so `@google/genai` is declared as a direct dependency of api-server (not just the lib) to resolve at runtime. Verified-video feature on the chat route: the model can request a video via a hidden `[[video?:search terms]]` marker (stripped server-side by `VideoMarkerStripper` in `src/lib/youtube/marker.ts`, which buffers tail fragments so a marker split across SSE chunks is never leaked; module/lab tokens pass through untouched). After the text stream completes, `resolveVerifiedVideo` runs only if BOTH `YOUTUBE_API_KEY` and `GEMINI_API_KEY` are set: `searchTrustedVideos` (`src/lib/youtube/search.ts`) hits the YouTube Data API v3 with the user's own `YOUTUBE_API_KEY` (mirrors the GEMINI key pattern; the YouTube OAuth connector was intentionally NOT used) filtered to a curated channel-ID allowlist (`src/lib/youtube/allowlist.ts` — NASA, Veritasium, Kurzgesagt, SciShow, Khan Academy, MIT, TED-Ed, 3Blue1Brown, etc.), then `scoreVideoRelevance` (Gemini structured pass, `thinkingBudget:0`) gates on a strict score ≥90 and returns at most ONE video. It is emitted as a single trailing `{ video: { id, title, channel } }` SSE event (parallel to `{ sources }`). Everything degrades gracefully (search/scoring never throws into the reply; missing key = no card). The model is instructed to never write raw YouTube URLs/IDs/names — the marker is the only path. Live talking-avatar ("Talk to {figure}") routes live in `src/routes/avatar.ts` (provider abstraction in `lib/integrations-avatar-server`, persona config in `src/lib/avatar/personas.ts`): `GET /api/avatar/figures/:slug` (public capability) plus `/avatar/sessions` (+ `/sdp`, `/ice`, `/say`, DELETE) which orchestrate D-ID streaming WebRTC + a Gemini persona brain + ElevenLabs voice. The feature is UNGATED (open to guests — `requireAuth` removed; an active session is protected by its unguessable random id, `AvatarSession.userId` nullable) and cost-bounded by a per-IP rate limit on `/sessions` + a hard per-session duration cap. Einstein's persona uses the account's cloned ElevenLabs "albert" voice; its portrait is the cleared Einstein image self-hosted at `artifacts/citizen-science/public/avatars/albert-einstein.jpg` (D-ID downloads `source_url` server-side and Wikimedia blocks data-center fetchers, so the portrait must be on our own origin) — personas store a site-relative path that `resolvePortraitUrl()` turns into an absolute URL (`PUBLIC_BASE_URL`/`REPLIT_DOMAINS`) at session start. See the `did-elevenlabs-avatar` memory for the full integration notes. Credit-based billing meters all AI features: `lib/db/src/schema/credits.ts` adds a `credit_accounts` table (unique `subjectKey`, `periodKey` YYYY-MM, `periodUsed`, `topupBalance`). Server logic lives in `src/lib/credits/`: `plans.ts` (`PLAN_MONTHLY_CREDITS` free 200 / researcher 2000 / pioneer 12000, `GUEST_MONTHLY_CREDITS` 50, `TOKENS_PER_CREDIT` 1000, `creditsForUsage`/`FALLBACK_CREDIT_COST` {chat:3,research:5,fieldNotes:2,avatar:2}), `subject.ts` (`resolveBillingSubject` + `ensureAnonId` — guests metered per browser via the `cs_anon` signed cookie), and `credits.ts` (`getCreditState`, `hasCreditsAvailable`, race-safe `consumeCredits` using a `FOR UPDATE` txn that spends monthly grant then top-ups, `addTopupCredits`, `nextRenewalDate` = start of next UTC month). The Gemini lib reports usage: `streamChat` yields a trailing `{ usage }` chunk and `analyzeFieldNotes` accepts `{ onUsage }`; routes meter actual tokens after the work completes (≈1 credit/1000 tokens, fixed fallback when usage is absent).
