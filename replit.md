# Workspace

## Overview

pnpm workspace monorepo using TypeScript. Each package manages its own dependencies.

## Stack

- **Monorepo tool**: pnpm workspaces
- **Node.js version**: 24
- **Package manager**: pnpm
- **TypeScript version**: 5.9
- **API framework**: Express 5
- **Database**: PostgreSQL + Drizzle ORM
- **Validation**: Zod (`zod/v4`), `drizzle-zod`
- **API codegen**: Orval (from OpenAPI spec)
- **Build**: esbuild (CJS bundle)

## Key Commands

- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- `pnpm --filter @workspace/api-server run dev` — run API server locally

See the `pnpm-workspace` skill for workspace structure, TypeScript setup, and package details.

## Artifacts

- **`artifacts/api-server`** — Express 5 API server. Auth routes under `/api/auth`: `POST /register`, `POST /login`, `POST /logout`, `GET /me`, plus Google OAuth `GET /google` (start, PKCE + state in signed cookies) and `GET /google/callback` (create-or-link user by email, set session cookie, redirect to `/login`). Sessions use a `cs_session` httpOnly signed cookie (30-day TTL); passwords are scrypt-hashed (`scrypt$salt$hash`, no external deps) in `src/lib/auth/`. `requireAuth` middleware (in `src/middlewares/`) gates the agent routes and `/me`. `app.ts` sets `trust proxy` and uses `cookie-parser` with `SESSION_SECRET`. Google OAuth uses the user's OWN `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` secrets (not a Replit connector); redirect_uri is derived from `REPLIT_DOMAINS` as `https://<domain>/api/auth/google/callback` — register both dev and prod callback URLs in Google Cloud Console. Other routes: `/api/healthz`, `POST /api/agent/chat` (SSE streaming, Gemini-backed science copilot), and `POST /api/agent/process-observation` (Gemini-backed field-notes analyzer). Both agent routes use `@workspace/integrations-gemini-ai-server`, which wraps `@google/genai` (model `gemini-2.5-flash`) using the user's own `GEMINI_API_KEY` — chosen because the Replit AI proxy (used by the OpenAI lib) is only reachable inside Replit and fails on Cloud Run. The chat route calls `streamChat(systemPrompt, messages, { signal, maxOutputTokens, useSearch })`, which maps assistant→`model`, trims leading non-user turns, and yields `StreamChatChunk` objects (`{ text?, sources? }`). When `useSearch` is true it enables the built-in Google Search tool for grounding and keeps thinking ON (with `thinkingBudget: 0` the model never decides to call Search and just answers from training data — known gotcha); when false it disables thinking for low latency. Grounding metadata (`groundingChunks[].web`) is de-duped and emitted as a single trailing `{ sources: [{ title, url }] }` chunk. The chat route runs the grounded pass first (with a larger 4096 token budget for thinking), and if it fails before any text is streamed (and the client hasn't disconnected) it gracefully falls back to an ungrounded pass via `req.log.warn`; SSE now also emits `{ sources }` events. The lib also exports `researchWithSearch(prompt, opts)` — a one-shot grounded call returning `{ text, sources }` — as the reusable web-research foundation. Note: Gemini source URLs are `vertexaisearch.cloud.google.com/grounding-api-redirect/...` redirect links and the `title` is the publisher domain. The process-observation route uses `analyzeFieldNotes` (with a `responseSchema`) using the user's own `GEMINI_API_KEY` secret (not Replit's managed Gemini integration — the user explicitly chose their own key); it validates a non-empty `rawText` body and returns `{ success, data }` structured JSON (summary, category, observations, tags, location, measurements, observedAt, species). Both agent routes are gated by the `requireAuth` middleware (valid `cs_session` cookie required). Stream cancellation on the chat route listens on `res.on("close")` (not `req`) and aborts the upstream Gemini request (via `AbortSignal`) when the client disconnects. Note: `build.mjs` externalizes `@google/*`, so `@google/genai` is declared as a direct dependency of api-server (not just the lib) to resolve at runtime. Verified-video feature on the chat route: the model can request a video via a hidden `[[video?:search terms]]` marker (stripped server-side by `VideoMarkerStripper` in `src/lib/youtube/marker.ts`, which buffers tail fragments so a marker split across SSE chunks is never leaked; module/lab tokens pass through untouched). After the text stream completes, `resolveVerifiedVideo` runs only if BOTH `YOUTUBE_API_KEY` and `GEMINI_API_KEY` are set: `searchTrustedVideos` (`src/lib/youtube/search.ts`) hits the YouTube Data API v3 with the user's own `YOUTUBE_API_KEY` (mirrors the GEMINI key pattern; the YouTube OAuth connector was intentionally NOT used) filtered to a curated channel-ID allowlist (`src/lib/youtube/allowlist.ts` — NASA, Veritasium, Kurzgesagt, SciShow, Khan Academy, MIT, TED-Ed, 3Blue1Brown, etc.), then `scoreVideoRelevance` (Gemini structured pass, `thinkingBudget:0`) gates on a strict score ≥90 and returns at most ONE video. It is emitted as a single trailing `{ video: { id, title, channel } }` SSE event (parallel to `{ sources }`). Everything degrades gracefully (search/scoring never throws into the reply; missing key = no card). The model is instructed to never write raw YouTube URLs/IDs/names — the marker is the only path. Live talking-avatar ("Talk to {figure}") routes live in `src/routes/avatar.ts` (provider abstraction in `lib/integrations-avatar-server`, persona config in `src/lib/avatar/personas.ts`): `GET /api/avatar/figures/:slug` (public capability) plus `/avatar/sessions` (+ `/sdp`, `/ice`, `/say`, DELETE) which orchestrate D-ID streaming WebRTC + a Gemini persona brain + ElevenLabs voice. The feature is UNGATED (open to guests — `requireAuth` removed; an active session is protected by its unguessable random id, `AvatarSession.userId` nullable) and cost-bounded by a per-IP rate limit on `/sessions` + a hard per-session duration cap. Einstein's persona uses the account's cloned ElevenLabs "albert" voice; its portrait is the cleared Einstein image self-hosted at `artifacts/citizen-science/public/avatars/albert-einstein.jpg` (D-ID downloads `source_url` server-side and Wikimedia blocks data-center fetchers, so the portrait must be on our own origin) — personas store a site-relative path that `resolvePortraitUrl()` turns into an absolute URL (`PUBLIC_BASE_URL`/`REPLIT_DOMAINS`) at session start. See the `did-elevenlabs-avatar` memory for the full integration notes. Credit-based billing meters all AI features: `lib/db/src/schema/credits.ts` adds a `credit_accounts` table (unique `subjectKey`, `periodKey` YYYY-MM, `periodUsed`, `topupBalance`). Server logic lives in `src/lib/credits/`: `plans.ts` (`PLAN_MONTHLY_CREDITS` free 200 / researcher 2000 / pioneer 12000, `GUEST_MONTHLY_CREDITS` 50, `TOKENS_PER_CREDIT` 1000, `creditsForUsage`/`FALLBACK_CREDIT_COST` {chat:3,research:5,fieldNotes:2,avatar:2}), `subject.ts` (`resolveBillingSubject` + `ensureAnonId` — guests metered per browser via the `cs_anon` signed cookie), and `credits.ts` (`getCreditState`, `hasCreditsAvailable`, race-safe `consumeCredits` using a `FOR UPDATE` txn that spends monthly grant then top-ups, `addTopupCredits`, `nextRenewalDate` = start of next UTC month). The Gemini lib reports usage: `streamChat` yields a trailing `{ usage }` chunk and `analyzeFieldNotes` accepts `{ onUsage }`; routes meter actual tokens after the work completes (≈1 credit/1000 tokens, fixed fallback when usage is absent). Both agent routes and the avatar `/sessions`+`/say` are credit-gated and return a structured `402 { error, outOfCredits:true, isGuest, upgradeHref }` (guest→`/login`, user→`/pricing`) when exhausted; metering failures fail open. `GET /api/billing/credits` (public, in `routes/billing.ts`, operationId `getCreditBalance`) resolves the user-or-guest subject and returns `CreditBalance { plan, isGuest, monthlyGrant, monthlyRemaining, topupBalance, totalRemaining, renewalDate }` (fails open to a full-grant view on read error). Note: `lib/db/drizzle.config.ts` `out` is now a RELATIVE path (`./migrations`) — drizzle-kit 0.31 prefixes `./` when validating existing snapshots, so an absolute `out` breaks `generate` (push is unaffected). Profile-ownership claims (Task #92, real backend replacing the old fake localStorage flow): `lib/db/src/schema/profileClaims.ts` (`profile_claims`: profileId→featured_profiles, userId→users, email, status pending/approved/denied, reviewedBy, reviewedAt, unique (profileId,userId)) + an `ownerUserId` column on `featured_profiles` (the API exposes a derived `verified` boolean = ownerUserId is set; `ownerUserId` itself is never serialized). Only LIVING innovators may claim — `src/lib/profiles/eligibility.ts` `isLivingProfile(era, lifespan)` treats a closed `YYYY–YYYY` range as historical/deceased (signal lives in `era`; `lifespan` is empty for all rows). Routes in `routes/profiles.ts`: `GET /api/profiles/:slug/claim` (auth-gated `MyProfileClaimStatus` { claimable, isOwner, email, claim }), `POST /api/profiles/:slug/claim` (creates a pending claim using the caller's own account email; 400 on non-living, conflict on existing claim/owned), `PATCH /api/profiles/:slug` (owner-only edit, 403 if not owner — fields summary/tagline/field/era/birthplace/imageUrl/biography/contributions/quotes). Superadmin review in `routes/admin.ts`: `GET /api/admin/claims?status=`, `POST /api/admin/claims/:id/approve` (txn: marks approved, sets `featured_profiles.ownerUserId`, auto-denies sibling pending claims on the same profile), `POST /api/admin/claims/:id/deny`.
- **`artifacts/mockup-sandbox`** — Component preview sandbox used during early design iteration on the canvas.
- **`artifacts/citizen-science`** — Citizen Science web app (React + Vite + TypeScript + Tailwind v4 + wouter). Premium minimalist science learning prototype. Auth is now real and backend-backed (Postgres + Drizzle via api-server): `src/lib/auth.tsx` is a context wrapping the generated `useGetCurrentUser`/`useLogin`/`useRegister`/`useLogout` hooks (session cookie `cs_session` sent same-origin). `/login` offers email+password (register toggle) and "Continue with Google" (`window.location.href = "/api/auth/google"`); the Google callback redirects back to `/login` with `?error=google` / `?error=google_unconfigured` on failure. `ProtectedRoute` shows a loading state while `useGetCurrentUser` resolves, redirects to `/login` if unauthenticated, and to `/onboarding` if not yet onboarded. Onboarding completion is still a `localStorage` flag (`cs_onboarded`); other app data persists in `localStorage` via `src/lib/storage.ts`. The old fake `cs_auth` localStorage flag and `x-cs-auth` header are gone. Routes: `/`, `/login`, `/onboarding`, `/dashboard`, `/agent`, `/categories`, `/category/:slug`, `/experiments`, `/experiments/:id`, `/notebook`, `/progress`, `/profile`, `/architecture`. The `/agent` route is the science copilot chat: the landing-page input writes the user's prompt to `localStorage.cs.pendingPrompt` and routes to `/login` (or directly to `/agent` if already authed). Login and onboarding both forward to `/agent` when a pending prompt exists. `Agent.tsx` auto-sends the pending prompt on mount, streams SSE replies from `POST /api/agent/chat`, and renders inline `[[module:slug]]` (and `[[lab:slug]]`) tokens as clickable cards. It also consumes `{ sources }` SSE events (Google Search grounding citations), de-dupes them by URL onto the assistant message, and renders a numbered `SourceList` of external links below the reply. It likewise consumes a trailing `{ video: { id, title, channel } }` SSE event and renders one embedded `VideoCard` (privacy-friendly `youtube-nocookie.com/embed/<id>` iframe with a YouTube icon + title/channel) below the reply. Conversation history (including sources and the video) persists at `localStorage.cs.agentConversation`. Public routes are `/` and `/login`; everything else is gated by `ProtectedRoute`. `/architecture` (`src/pages/Architecture.tsx`, public, standalone — no AppShell) is an interactive system-architecture diagram built with React Flow (`@xyflow/react`, a devDependency): a single custom `flow` node type, two toggleable scenes ("Runtime" request-flow and "Deployment" pipeline) defined as plain node/edge arrays, click-a-node to highlight its connected edges + show a detail panel (others dim), plus legend, minimap and pan/zoom. The diagram content is hand-maintained to mirror this README, so update it when the architecture changes. Gotcha: TSX generic type args on a JSX element (e.g. `<ReactFlow<AppNode, Edge>>`) break Replit's vite-plugin-react babel metadata transform — rely on prop type inference instead of explicit JSX generics. The public landing page (`/`, `Landing.tsx`) is positioned as a Future Vision XPRIZE "Humanity's Research Network™" page — a cinematic, aspirational single-page narrative (dark hero + dark interludes alternating with light editorial sections, framer-motion `Reveal` scroll-in wrapper, Instrument Serif display headlines) with a dark sticky header and anchor nav (Vision/Discover/Participate/Impact/Community + Join→/login). Section order: cinematic hero, "The Greatest Untapped Resource… It's People" belief, "The Future We Are Building" (3 pillars), "Imagine 2045" interlude, "The Discovery Flywheel™" (custom CSS ring of 6 stage nodes on md+, wrapped chip flow on mobile), "Areas of Impact" (8 cards), "Why This Matters" (today vs tomorrow), "By The Numbers" (dark stats band), a Discover block that embeds the live `AskAgent` copilot + `RotatingDashboardCard` + an 8-card categories preview, "Participate" pathways (Participate/Partner/Educate/Build), a Community inventors showcase, and a closing manifesto CTA. The earlier feature-marketing sections (Problem/Workflow/How It Works/Featured Tools/Safety/Connect Devices) were removed in this repositioning; the now-unused `TOOLS`/`DEVICES` consts/imports remain (harmless — `noUnusedLocals` is off). 14 science categories live in `src/lib/categories.ts`, starter experiments in `src/lib/experiments.ts`. The homepage Community/inventors grid is a curated static array in `src/lib/inventors.ts` (Manu Rehani featured first, photo imported via the `@assets` alias from `attached_assets/`; the other 7 are well-known inventors with Wikipedia portraits/links) — independent of the DB. Brand palette in `src/index.css`: bg `#F8FAFC`, text `#0F172A`, blue `#2563EB`, green `#16A34A`, violet `#7C3AED`. Inter for sans, Instrument Serif for hero headlines. The cinematic "great mind" story layout (`/directory/:slug` → `ProfileDetail.tsx` → `GreatMindStory.tsx`) now scales beyond the original 8 hand-authored figures (Einstein, Curie, Tesla, Darwin, Newton, Galileo, Lovelace, Turing). `src/lib/greatMinds.ts` exports `deriveStoryTheme(field)` (a DISCIPLINE_THEMES keyword map → per-field default `StoryTheme`, so new figures get a sensible palette with zero per-person styling) and `buildStoryFromProfile(profile)` (turns a DB `FeaturedProfile` row into a `GreatMindStory`, or returns null when the row has no biography/summary so the page falls back to the standard layout). Render precedence in `ProfileDetail.tsx`: hand-authored frontend story → DB-built story (from `useGetFeaturedProfile`) → standard profile layout. `GreatMindStory.tsx` degrades gracefully — hero tagline/lifespan/birthplace, portrait, and contribution titles are all conditional, so a partial row still renders cleanly. A second static tier `CURATED_HISTORICAL` (8 more real figures: Hawking, Feynman, Faraday, Pasteur, Pauling, Bohr, Hopper, Franklin) is registered into `GREAT_MIND_STORIES` at module load using `deriveStoryTheme` (authored entries win on slug collision); these render WITHOUT the DB, satisfying the decoupling requirement. The DB half lives in `lib/db/src/schema/featuredProfiles.ts` (optional story columns: tagline, lifespan, birthplace, biography[], timeline[], storyContributions[], legacy[], didYouKnow[], storyTheme) mirrored in `lib/api-spec/openapi.yaml`; `storyTheme` is left null by the seeder so the frontend derives it. Repeatable population is `scripts/src/seed-stories.ts` (`pnpm --filter @workspace/scripts run seed-stories`) — a grounded-Gemini, idempotent/resumable generator (mirrors seed-profiles: skips rows whose biography is already populated, enriches base rows in place, paced with 429 back-off) over a `HISTORICAL_FIGURES` list; it derives the flat `contributions[]` from the story cards and sets `summary` from the first biography paragraph so the row reads in both layouts. Pricing (`src/pages/Pricing.tsx`) is a credit-based 3-tier model — Free ($0, ~200 credits/mo), Researcher ($20/mo, ~2000, featured), Pioneer ($100/mo, ~12000) — plus a `TopupPacks` section of placeholder one-off credit packs (disabled "Coming soon" buttons, no real payment) and a credit-focused FAQ; the Founding Member ($2,500 lifetime) section is kept and the old Educator/Institution tiers + monthly/annual toggle were removed. `src/components/CreditMeter.tsx` exports `useCreditBalance()` (wraps the generated `useGetCreditBalance` hook with a queryKey + 15s staleTime) and a `CreditMeter` component (`full` variant in the Sidebar, `compact` pill in the Agent header) showing plan + remaining/total credits with a usage bar that links to `/pricing`. `Agent.tsx` handles the `402 { outOfCredits, isGuest, upgradeHref }` response distinctly (sets `limitInfo` and refetches the balance) and refetches credits in the stream `finally` so the meter stays current. Profile claiming/editing (Task #92) is now real-backend, not fake localStorage (the old `storage.getClaimedProfiles/isProfileClaimed/claimProfile` helpers were removed). `src/components/ProfileOwnership.tsx` is a layout-agnostic fixed overlay rendered by `ProfileDetail.tsx` alongside whichever of the 4 layouts is chosen, so the affordance works everywhere: it shows a "Claim this profile" CTA to the living innovator (guests are routed to `/login`; signed-in users POST a claim via `useClaimProfile`), a "pending review" state, a "Verified" badge to visitors, and for the approved owner a "Verified — Edit my profile" button opening an editor dialog (PATCH via `useUpdateMyProfile`; newline-separated textareas for biography/contributions/quotes). `src/lib/profileClaim.ts` `isClaimableProfile(era, lifespan)` mirrors the server's living-innovator rule so the CTA shows correctly to logged-out visitors. CRITICAL precedence change in `ProfileDetail.tsx`: when a profile is `verified` (owned), the hand-authored GreatMindStory/LivingMindStory layouts are SKIPPED so the owner's DB-stored edits are authoritative (falls through to DB-built story or standard layout). The Admin portal (`src/pages/Admin.tsx`) has a "Claims" tab (`ClaimsTab`) listing claims with a status filter and approve/deny actions (`useListAdminClaims`/`useApproveClaim`/`useDenyClaim`).
